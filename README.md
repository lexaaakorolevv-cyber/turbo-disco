# Route Finder 2.1.0

**Поиск веток через реальную физику Geometry Dash**, запись и точный повтор ввода, независимые P1/P2 и JSON. Windows x64, GD **2.2081**, Geode SDK **5.11.1** (пакет совместим с загрузчиком 5.11.2). C++23.

[Скачать Windows .geode 2.1.0](https://github.com/lexaaakorolevv-cyber/turbo-disco/raw/refs/heads/route-finder-windows/downloads/local.routefinder-windows-x64-v2.1.0.geode)

В 2.1 изменён способ поиска: числовой прогноз только предлагает порядок нажатий. Каждая испытываемая последовательность проходит через настоящий игровой update и настоящие столкновения. После смерти выбирается ещё не испытанная кнопка в дереве решений; для возврата выполняется полный штатный сброс и повтор точного префикса. Состояние мира по координатам/скоростям не восстанавливается.

## Установка и управление

1. Закройте игру. Замените старый `local.routefinder` в `Geometry Dash/geode/mods` новым файлом; оставьте один пакет с этим ID. Pathfinder с ID `ademyanov.pathfinder` — другой мод; одновременно запускать двух управляющих вводом ботов нельзя.
2. Откройте обычный уровень с начала → штатная пауза → **BOT** → **«Найти прохождение»**.
3. Во время уровня показывается только лучший процент. Все кнопки находятся в светлом меню паузы: поиск, остановка, ручная запись, повтор, сохранение, загрузка, Analyze, настройки.
4. По умолчанию включён `Search using live game outcomes`. Старый приблизительный поиск можно включить, отключив эту настройку. Для нового дерева с новым шагом отключите `Resume compatible v2 search session` на один запуск.
5. **«Записать вручную»** записывает нажатия и отпускания; **«Воспроизвести»** повторяет выбранную запись с начала без решений бота. Полный макрос заново проверяется в игре, даже если файл содержит `verified: true`.
6. **Analyze** строит структурную карту в паузе; готовая карта помогает только порядку решений. Поиск доступен без Analyze. Закрытие меню отменяет незавершённый анализ.

## Как устроен новый поиск

- Решение принимается каждые **2 внешних физических тика 240 Hz**; настройка позволяет 1–8. Запись ввода при этом остаётся на каждом положительном `processCommands`, включая half steps.
- В обычном/shared-dual режиме рассматриваются удержание и отпускание общей кнопки. В независимом 2-player — все четыре совместные комбинации P1/P2. Нажатия, запрещённые текущим **16 CPS на канал**, не попадают в дерево; отпускание не задерживается.
- Дерево хранит ещё не испытанные альтернативы и точный префикс действий. Между решениями кнопка сохраняет состояние, поэтому возможны короткие нажатия и длительные зажимы ship/wave/robot.
- Успех/смерть поступают из настоящей игры. Высокий процент не удаляет ранние маршруты. Каждую восьмую смерть окно возврата расширяется по детерминированному расписанию: 32, 64, 128… тиков. Это ограниченный перебор с отбросом части поздних поддеревьев, **не полный обход всех возможных последовательностей**.
- При повторе проверяются часы, граница dt/half/last, количество действий, удержания, признаки контактов и числовое состояние игроков в сохранённых решениях. Расхождение останавливает поиск с причиной; отличающееся состояние не считается доказанным тупиком.
- При настоящем завершении кандидат отдельно проходит **полный повтор с начала** с обычной скоростью. Проверяются шаги, трасса обоих игроков и реальное завершение. Только затем создаётся проверенный `macro.json`.

Прогнозы в `src/physics` всё ещё приблизительные. В режиме native они ограничены **4096 операциями развёртки** на новое планирование и служат порядком обхода, а не доказательством выживания. Любые движущиеся объекты/скрипты исполняет игра; неполная геометрия подсказки может ухудшать порядок поиска, но не позволяет пройти сквозь препятствие в настоящей попытке.

## Производительность и лимиты

Штатный поиск идёт с обычной скоростью игры. Возврат через полный повтор может быть заметно медленнее ботов с неполными snapshot-состояниями. Внутри кадра пачка игровых обновлений ограничена бюджетом **2 ms**, а подсказка — фиксированным числом операций, одинаковым на разных ПК. Один native update/расчёт нельзя прервать посередине, поэтому это не жёсткая гарантия FPS.

`Accelerate native search` — **экспериментальная, по умолчанию выключенная** настройка: до 128 фиксированных обновлений на кадр в пределах того же бюджета. Render-time действия и звуковые механики могут расходиться с обычным темпом; найденный кандидат всё равно обязан пройти отдельный повтор в реальном времени. При проблемах ускорение следует выключить.

Лимиты: 10 000 попыток, 1 час, 600 секунд симуляции на попытку, 3 000 000 решений, 32 768 решений в активном пути. В настройках меняются попытки, время, интервал, общий предел решений и бюджет кадра. При возобновлении сохраняется прежний интервал дерева; текущий общий предел решений применяется заново. При лимите сохраняются лучший участок, дерево поиска, счётчики и причина остановки.

Сеанс автоматически сохраняется не чаще раза в 3 секунды; остановка и завершение требуют сохранения сразу. Снимок содержит только числа; JSON дерева и файловый ввод-вывод выполняются отдельным работником, очередь объединяет устаревающие задания.

## Файлы и совместимость

Каталог: `Mod::get()->getSaveDir()/v2/<level-id>_<data-hash>/`.

- `best.json` — лучший участок/кандидат, в том числе неполный.
- `search.json` — дерево решений или старый архив, префикс следующей попытки, калибровка и лимиты; можно продолжать поиск после остановки.
- `macro.json` — только успешный макрос после полного проверочного повтора.
- `.bak` — предыдущая версия; запись через временный файл и переименование.

Действие: `[tick, down, button, player]`. Сохраняются ID/хеш/ревизия и настройки уровня, версии GD/SDK/мода/загрузчика, список модов, платформа, настройки физики/управления, seed, LDM и фактическая последовательность `dt/half/last`. Файлы старых версий сохраняются, но несовпадающее окружение запрещает их автоматическое исполнение.

## Границы поддержки

Поддержаны классические режимы cube, ship, wave, ball, UFO, robot, spider, swing, shared dual и независимый 2-player. Не поддержаны platformer, editor/native replay, practice, StartPos/Don't Reset, поворот оси на 90°, random/item persistence, noclip/ignore damage, time warp и CBS/COS. Изменение управления/физики останавливает операцию.

Перебор растёт экспоненциально, длинный или сложный уровень может оказаться непосильным. Ограниченный выбор тиков и отброс поддеревьев также могут пропустить решение. Прохождение любого уровня не обещается.

В среде разработки нет запущенной Geometry Dash. Нативная сборка и переносимые сценарии проверены отдельно; реальное прохождение, UI и FPS на ПК здесь не измерены. Данные из присланного `.geode` использованы как справочная информация: исходников внутри нет, DLL/ресурсы не переносились. Подробности: [REFERENCE.md](REFERENCE.md).

## Сборка Windows

Нужны Visual Studio 2022 с C++23, CMake ≥3.25, официальный Geode CLI **3.9.0** в PATH и SDK **5.11.1**. Скачайте SDK из тега `v5.11.1` репозитория geode-sdk/geode и Windows-библиотеки из релиза Geode `v5.11.1`; распакуйте библиотеки в `SDK/bin/5.11.1` (там должен находиться `Geode.lib`). Bindings закреплены SHA в `cmake/Bindings.cmake`.

```powershell
$env:GEODE_SDK = "C:\dev\geode-sdk"
cmake -S . -B build-win -A x64 -DGEODE_DISABLE_PRECOMPILED_HEADERS=ON
cmake --build build-win --config Release --parallel 4
```

Результат: `build-win/local.routefinder.geode`. Тот же процесс описан полностью в `.github/workflows/windows.yml`.

Проверки без игры/SDK:

```sh
cmake -S . -B build-core -DROUTEFINDER_CORE_ONLY=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build-core --config Release --parallel 4
ctest --test-dir build-core -C Release --output-on-failure
```

Архитектура и границы модулей: [ARCHITECTURE.md](ARCHITECTURE.md). Доказательства сборки и пределы проверок: [VALIDATION.md](VALIDATION.md).
