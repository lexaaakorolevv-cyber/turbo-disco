# Route Finder 1.11.1 — Geode / C++

Запись физического ввода, ограниченный поиск прохождения и отдельная проверка полного повтора с начала. Поддерживаются solo, shared-dual и независимый 2-player. Прохождение любого уровня не гарантируется.

Совместимость закреплена: **Geometry Dash 2.2081**, **Geode SDK 5.11.1**, C++23. Пакет Windows содержит DLL x64. Настоящая игра и её FPS в среде сборки недоступны.

[Скачать .geode 1.11.1 для Windows x64](https://github.com/lexaaakorolevv-cyber/turbo-disco/raw/refs/heads/route-finder-windows/downloads/local.routefinder-windows-x64-v1.11.1.geode)

## Управление

Во время игры мод показывает **только лучший процент** в правом верхнем углу. Кнопок, панелей, траекторий, счётчиков попыток и CPS в игровом HUD нет. Рекорд привязан к ID и хешу данных уровня, сохраняется в данных Geode. Он показывает достигнутый процент; отметкой проверенного макроса не является.

Все кнопки доступны через **штатная пауза → BOT**. На экране завершения кнопка мода также удалена: для нового повтора нажмите обычный replay игры, затем откройте паузу.

- **Бот:** **Analyze** (карта и разбор уровня), «Найти прохождение», «Остановить», «Ручная помощь / Вернуть управление боту», попытки, лучший процент, время и причина остановки.
- **Макрос:** «Записать вручную», «Сохранить макрос», «Загрузить макрос», «Воспроизвести».
- **Настройки:** «Нагрузка: ниже / обычная» и лимиты поиска через настройки Geode.

Меню мода останавливает симуляцию, но не музыку. Для просмотра с музыкой запустите повтор заново. Время открытой паузы входит в общий лимит работы.

## Analyze — анализ уровня

Откройте уровень → пауза → BOT → **Analyze**. Дождитесь «АНАЛИЗ ГОТОВ», нажмите «Готово», затем «Найти прохождение». В окне есть «Повторить» и «Стоп»; закрытие незавершённого анализа отменяет его. Поиск/запись/повтор перед анализом нужно остановить.

Сканируются текущие загруженные объекты: блоки/склоны, опасности, орбы, пады, порталы форм, гравитации, размера, скорости и solo/dual. Отчёт показывает формы, количество механик, кандидаты связок, приблизительную карту переходов по X и ограничения. Будущие события порталов не считаются гарантированными: персонаж может пройти мимо. Это не готовый макрос и не полное прохождение на виртуальной копии GD.

Результат используется в поиске: перед разнесённой связкой или серией препятствий прогноз расширяется с обычного горизонта до 98 native единиц (~1,63 с). Для ship/wave ограниченный граф свободных вертикальных коридоров отбрасывает видимые тупиковые ветви и задаёт мягкую цель по высоте. Ускорение корабля, 16 CPS и реальные столкновения проверяет рабочий прогноз/игра; граф сам по себе не доказывает выполнимость. В dual высота запрашивается для каждого настоящего персонажа. Перед native-переходом формы/скорости/dual расширенная структурная подсказка отключается. Неизвестные игровые триггеры, условные объекты и слишком плотная карта дают консервативный отказ от подсказки.

Чтение native-объектов идёт только в открытом окне анализа, до 512 за UI-кадр с кооперативной целью 2 мс. Сортировка, структура, текст и JSON обрабатываются в фоне над копиями чисел; методы/указатели игры туда не передаются. Лимит снимка — 250000 объектов, превышение сообщается явно. Во время поиска вся карта заново не сканируется: используется индекс; запрос ограничен 4096 записями и 128 прямоугольниками для 32 срезов связности. Обычный прогноз не обрывается по render-бюджету. Расширенный прогноз может требовать больше CPU на сложных участках.

JSON-отчёт `<id>_<hash>.analysis.json` сохраняется в `Mod::get()->getSaveDir()/macros` с окружением, версиями и хешем уровня. Подсказка хранится в памяти до выхода из уровня; отчёт автоматически не загружается, чтобы старый снимок не стал источником геометрии. После повторного входа нажмите Analyze заново. Макросы и поиск прошлых версий требуют нового поиска из-за смены версии окружения.

## Что изменилось

**Исправление 1.10.1.** Удалён общий render-бюджет из игрового управления. Прогноз снова доходит до своего горизонта, а отпускание/перестройка после события не пропускаются из-за занятости предыдущими расчётами. Интерфейс и безопасные оптимизации 1.10.0 сохранены. Новые тесты воспроизводят старую ошибку и сверяют одинаковые действия по физическим тикам при 15, 30, 60, 144 и 240 условных FPS.

**Калибровка физики.** По штатным наблюдениям отдельно для двух персонажей уточняются гравитация, прыжки cube/robot и импульс шара, четыре ветви ускорения корабля, наклон волны, взмах UFO, реакция swing и длительность зажима робота. Для мини/гравитации — отдельные корзины. Установленная оценка защищена от одиночного выброса; измеряется разброс. Параметры без подходящих измерений остаются номинальными. Измерения после орба, dash, телепорта, склона и смены формы отсекаются. Это уточнение приближённой модели, не полная копия физики GD.

**Разбор смертей.** Для каждого персонажа хранится до 120 последних наблюдений. По ним и геометрии столкновения строится предположение о позднем/раннем нажатии, лишнем зажиме или неверном маршруте. Очередь правок учитывает конкретного игрока и ближайшее относящееся к ошибке действие. UFO/swing не смешиваются с непрерывным зажимом корабля. Неизвестное столкновение не получает выдуманной точной причины. Ошибки P2 не штрафуют P1 в независимом режиме.

**Связки.** При двух предстоящих орбах/падах общий прогноз смотрит до 66 native единиц (около 1,1 с), сохраняет варианты с разными использованными взаимодействиями и учитывает дальнейшую посадку и препятствия. Отбор ближайших взаимодействий сохраняет стабильные индексы орбов. Орбы, пады, гравитационные/size порталы исполняет сама игра. Прогноз заканчивается на переходе формы, скорости или solo/dual и перестраивается по настоящему состоянию.

**Альтернативные маршруты.** Архив до 24 последовательностей сначала сохраняет различающиеся ранние решения, затем близкие варианты таймингов. Вместе с маршрутом сохраняются политика и число использований. При застое перебор чаще возвращается к мало использованным вариантам рядом с лучшим процентом, меняет хвост, а при долгом застое пробует новый маршрут. Успешные участки повторяются с начала; чекпоинты и восстановление мира не применяются.

## Нагрузка

Исправлена регрессия 1.10.0: общий предел 6000 вариантов / 3 мс на render frame мог прерывать прогноз до важного прыжка, удерживать устаревший ввод и менять результат при смене FPS. В 1.10.1 native-контроллеры всегда завершают полноценный ограниченный по глубине прогноз, как в 1.9.0. На переходе/контакте разрешён необходимый новый расчёт независимо от числа уже прошедших шагов кадра.

«Нагрузка: ниже» переиспользует неизменившееся решение на физических подшагах и короткий проверяемый план действий; «Обычная» чаще пересчитывает решение. Обе настройки сохраняют полный горизонт. Жёсткого лимита миллисекунд нет: на плотных участках расчёт может занимать больше времени. Обещать отсутствие задержек или лучший FPS без запуска на вашем ПК нельзя.

Линии прогноза и деревья для их отображения во время игры не строятся. HUD проверяет изменение процента до 5 раз/с. Списки типов объектов, отбор по горизонтали, общие срезы геометрии и индекс памяти ошибок сохраняются. Пути/хеши окружения для автосохранения берутся из подготовленного окружения.

Сериализация больших JSON и файловые записи автосохранения выполняются фоновым работником над копиями чисел и последовательностей. У него не больше одного выполняющегося и одного ожидающего снимка; новые ожидающие снимки одного уровня объединяются. Объекты/методы игры в фоновом потоке не используются. Остановка, ручная загрузка и финальное сохранение дожидаются очереди, чтобы старый снимок не перезаписал новый результат. Небольшое копирование снимка остаётся на игровом потоке.

Замеры стенда и ограничения: [docs/PERFORMANCE.md](docs/PERFORMANCE.md). Нулевые задержки и определённый FPS на любом компьютере не обещаются.

## Запись, поиск и повтор

1. Откройте простой уровень → пауза → BOT → «Макрос» → «Записать вручную». Игра начинается с начала; реальные press/release округляются к следующей физической границе.
2. После смерти сохраняется черновик. После полного кандидата автоматически запускается отдельный повтор с начала.
3. Для поиска: пауза → BOT → «Бот» → «Найти прохождение». Каждая попытка выполняется настоящей игрой. После смерти меняются действия перед неудачным местом.
4. Для помощи боту: пауза → BOT → «Ручная помощь», затем аналогично верните управление. Ввод помощи записывается; в независимом 2-player сохраняются обе стороны управления.
5. «Остановить» прекращает поиск, освобождает оба канала и сохраняет лучший достигнутый участок. При исчерпании лимита статус объясняет причину.
6. «Загрузить макрос» берёт основной файл уровня, при его отсутствии — лучший черновик. «Воспроизвести» повторяет только сохранённые события. Неполный макрос останавливается на своём конце.

Успешный основной JSON сохраняется только после совпавшего полного повтора с начала: проверяются каждый физический шаг, оба персонажа, переходы solo/dual и завершение уровня. Загруженный флаг verified сам по себе не считается доказательством.

Поиск/помощь ограничены **16 CPS на канал**. Удержание не обрывается, отпускание не задерживается. Ручная запись и replay не фильтруются новым ограничителем. В независимом 2-player P1/P2 могут нажимать на одном тике; Flip 2-Player Controls учитывается, его изменение во время операции останавливает работу.

## Лимиты и сохранения

По умолчанию: 10000 попыток, 3600 секунд общего времени, 600 секунд симуляции на попытку, окно мутации 120 физических тиков, seed 1337. Существующие настройки пользователя сохраняют приоритет. Проверка кандидата входит в лимит; последний непроверенный кандидат остаётся черновиком. Абсолютный предел записи — 432000 физических тиков.

В `Mod::get()->getSaveDir()/macros` находятся `<id>_<hash>.json` (полный проверенный результат), `.best.json` (лучший участок) и `.search.json` (архив, RNG, очередь и обучение). Автосохранение — каждые 30 секунд, новый лучший результат — не чаще пяти секунд; полный кандидат ставится в очередь сразу. Resume saved search включён. Для нового независимого поиска выключите его. Несовместимые версии/уровень/физика/список модов отклоняются; старые макросы/сеансы 1.9.0 и 1.10.0 требуют нового поиска.

Загрузчик ограничивает JSON 128 MiB, проверяет структуру, порядок событий, числа и диапазоны. Файлы заменяются через временный файл/переименование с `.bak` на Windows. Аварийное завершение может потерять изменения после последнего сохранения.

## Границы поддержки

Контроллеры cube/ship/wave/ball/UFO/robot/spider/swing, shared-dual и независимого 2-player имеют ограниченные прогнозы. Сложные dash/custom/teleport механики, будущие скриптовые движения, free/sideways оси предсказываются не полностью; для sideways поиск явно останавливается. На плотном участке используются до 512 препятствий и 48 взаимодействий на персонажа. Прогноз движения объектов ограничен ближайшими наблюдаемыми скоростями.

Отклоняются platformer, practice, Start Position, Don't Reset, editor, встроенный replay, noclip, random triggers, item edit/compare/persistence. CBS/COS временно выключаются и затем восстанавливаются. Внешние speedhack/TPS/CBF/replay-моды могут менять физику вне адаптера; контроль повторного прохождения обнаруживает многие расхождения, но не исправляет их.

## Сборка и установка

Windows: Git, CMake 3.25+, Geode CLI 3.9.0 и Visual Studio 2022 17.14+ (MSVC 19.44+) либо VS 2026. PowerShell:

```powershell
git clone --branch v5.11.1 --depth 1 https://github.com/geode-sdk/geode.git C:/dev/geode-sdk
geode sdk set-path C:/dev/geode-sdk
geode sdk install-binaries --version v5.11.1
$env:GEODE_SDK = "C:/dev/geode-sdk"
cmake -S . -B build-win -A x64
cmake --build build-win --config Release --parallel 4
```

Результат: `build-win/local.routefinder.geode`. CMake требует SDK ровно 5.11.1, загружает закреплённые bindings и nlohmann/json с контрольной суммой. Зависимости/SDK не входят в исходный архив мода. Официальные загрузки: [Geode](https://github.com/geode-sdk/geode/releases/tag/v5.11.1), [CLI](https://github.com/geode-sdk/cli/releases).

Для Android ARM64 на Linux используются NDK r29, Ninja, официальный `Geode.android64.so` в `<SDK>/bin/5.11.1/` и параметры CMake `-DCMAKE_TOOLCHAIN_FILE=<NDK>/build/cmake/android.toolchain.cmake -DANDROID_ABI=arm64-v8a -DANDROID_PLATFORM=android-23 -DANDROID_STL=c++_shared -DGEODE_DISABLE_PRECOMPILED_HEADERS=ON`. ARM32 здесь не проверялся.

Установка: закройте игру, удалите прежний Route Finder `.geode` из `Geometry Dash/geode/mods`, скопируйте новый пакет Windows, перезапустите. Откройте **паузу → BOT**, проверьте **v1.11.0** и начните новый поиск. Пакет Android не содержит Windows DLL.

Переносимые тесты без игры:

```sh
cmake -S . -B build-core -DROUTEFINDER_CORE_ONLY=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build-core --parallel 4
ctest --test-dir build-core --output-on-failure
```

Десять наборов включают JSON/файлы, поиск/сессии, независимые простые трассы форм, shared-dual/2-player, калибровку, анализ смертей, лимиты расчётов, связку двух орбов с посадкой и фоновое сохранение. Это не прохождение настоящей GD. Результаты и сценарии на устройстве: [VALIDATION](docs/VALIDATION.md), реальные API: [API](docs/API.md), формат: [FORMAT](docs/FORMAT.md).
