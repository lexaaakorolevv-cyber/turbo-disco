# Route Finder 2.0.0

Новая архитектура мода Geometry Dash: точная запись ввода, проверяемый повтор, ограниченный поиск маршрутов и отдельный адаптер Geode. Windows x64, **GD 2.2081 / Geode SDK 5.11.1**, C++23. Любой уровень пройти не обещается.

Это переписанный управляющий слой: прежние Runtime, меню, архив поиска, протокол записи и файловый работник заменены. Проверенные математические прогнозы движения, геометрия столкновений и анализ коридоров перенесены в `src/physics`. Они по-прежнему приблизительные; переписывание архитектуры не превращает прогноз в настоящий симулятор Geometry Dash.

[Скачать Windows .geode 2.0.0](https://github.com/lexaaakorolevv-cyber/turbo-disco/raw/refs/heads/route-finder-windows/downloads/local.routefinder-windows-x64-v2.0.0.geode)

## Установка и управление

1. Закройте Geometry Dash. Удалите прежний `local.routefinder` .geode из `Geometry Dash/geode/mods` и положите новый файл. Одновременно должен быть установлен один пакет с этим ID.
2. Откройте обычный уровень → штатная пауза → **BOT**.
3. **«Записать вручную»** записывает реальные нажатия/отпускания на следующих физических границах. Остановите через паузу. **«Воспроизвести»** повторяет выбранную запись с начала.
4. **«Найти прохождение»** запускает ограниченный поиск. Рекорд — отдельный показатель; выбор ветки учитывает неудачи и число попыток. Более ранняя ветка может получать новые попытки при меньшем проценте.
5. **Analyze** считывает геометрию порциями в паузе и строит числовую карту/коридоры в фоне. Дождитесь готовности; повторное нажатие открывает отчёт. Закрытие меню или «Остановить» отменяет незавершённый анализ. Поиск доступен и без него.
6. **«Остановить»**, **«Сохранить макрос»**, **«Загрузить макрос»**, **«Воспроизвести»**, лимиты и запись доступны только в паузе. Во время игры отображается только лучший процент.

Обычный cube использует портфель наземного и общего контроллеров. Ship/wave поддерживают удержания и отпускания; ball/UFO/robot/spider/swing используют модель форм. Поддержаны shared dual и независимые кнопки двух игроков. Поиск ограничен **16 CPS на каждый канал**; отпускание не задерживается. Повтор ручной записи сохраняет исходный ввод точно.

При первом успешном завершении движок ещё не сохраняет результат как проверенный. Он перезапускает уровень и повторяет **только найденные действия**, без планировщика. Лишь после совпадения физических шагов, контрольных состояний обоих игроков и реального завершения уровня появляется `macro.json` с проверенным результатом.

## Сохранения и откат

Каталог: `Mod::get()->getSaveDir()/v2/<level-id>_<data-hash>/`.

- `best.json` — лучший записанный участок или кандидат; может быть неполным/непроверенным.
- `search.json` — архив веток, выбранный кандидат, калибровка, попытки и время для продолжения поиска.
- `macro.json` — успешный макрос после полного проверочного повтора.
- `.bak` — предыдущая версия файла; запись выполняется через временный файл и переименование.

JSON содержит ID/хеш/ревизию уровня, хеш настроек уровня, версии игры/SDK/мода/загрузчика, платформу, список загруженных модов, шаг/границу ввода, настройки управления, LDM, seed и фактическую последовательность физических dt/half/last. Действие: `[tick, down, button, player]`. Тики считаются по положительным вызовам `processCommands`, включая half steps, а не по кадрам отрисовки.

Собственные контрольные точки — подтверждённые **префиксы ввода**, а не сохранённый мир. Префикс и состояния должны совпасть в двух разных попытках. Откат всегда делает штатный сброс и повтор с начала до точки; затем ищет продолжение. При расхождении точка отключается. Телепорта назад или неполного восстановления игровых объектов нет.

Форматы 1.x не импортируются автоматически. Они остаются в прежнем каталоге сохранений, отдельно от v2. Лучший процент уровня подхватывается из прежнего счётчика. Для чистого поиска отключите `Resume compatible v2 search session` в настройках мода.

## Ограничения

Не поддержаны platformer, editor/native replay, practice, StartPos/Don't Reset, поворот оси на 90°, random/item persistence, noclip/ignore damage, time warp и CBS/COS. Изменение управления/физики во время попытки останавливает операцию.

Произвольные move/toggle/spawn/custom/dash/teleport механики не моделируются полностью. Анализ является структурной подсказкой. Плотные сцены ограничены ближайшими 512 препятствиями и 48 взаимодействиями на игрока. Сложный или memory-уровень может потребовать слишком много попыток; при лимите сохраняется лучший участок и причина остановки.

В среде разработки нет запущенной Geometry Dash. Сборка и числовые тесты не подтверждают реальное прохождение уровней, удобство UI или FPS на пользовательском ПК.

## Сборка Windows

Нужны Visual Studio 2022 с C++23, CMake ≥3.25, официальный Geode CLI **3.9.0** в PATH и SDK **5.11.1**. Скачайте SDK из тега `v5.11.1` репозитория geode-sdk/geode и Windows-библиотеки из релиза Geode `v5.11.1`; распакуйте библиотеки в `SDK/bin/5.11.1` (там должен находиться `Geode.lib`). Bindings закреплены SHA в `cmake/Bindings.cmake`.

```powershell
$env:GEODE_SDK = "C:\dev\geode-sdk"
cmake -S . -B build-win -A x64 -DGEODE_DISABLE_PRECOMPILED_HEADERS=ON
cmake --build build-win --config Release --parallel 4
```

Результат: `build-win/local.routefinder.geode`. Тот же процесс описан полностью в `.github/workflows/windows.yml`.

Проверки без игры/SDK:

```sh
cmake -S . -B build-core -DROUTEFINDER_CORE_ONLY=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build-core --config Release --parallel 4
ctest --test-dir build-core -C Release --output-on-failure
```
