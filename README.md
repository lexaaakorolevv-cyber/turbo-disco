# Route Finder — мод Geode на C++

Записывает ручной ввод по физическим шагам, воспроизводит его с начала уровня и ищет прохождение перебором последовательностей. После первого успешного кандидата автоматически запускает полную проверку с начала. Только повторное успешное завершение позволяет сохранить основной макрос как проверенный.

**Закреплённая совместимость:** Geometry Dash **2.2081**, Geode SDK **5.11.1**, C++23. Подготовлены отдельные пакеты Windows x64 и Android ARM64. Сборка, упаковка и тесты ядра проверены на Windows в GitHub Actions; сборка ARM64 проверена локально. Выполнение в самой игре не проверялось. Версии установленной у вас игры здесь недоступны; не устанавливайте пакет на другую версию GD.

Версия **1.6.0** добавляет семь улучшений: калибровку прогноза по наблюдаемой физике, модели орбов/падов/порталов, управление всеми восемью формами, краткосрочный прогноз движущихся препятствий, память неудач, отображение траектории и ручную помощь во время поиска. Сохраняются **16 CPS**, автосохранение поиска и обязательная полная проверка найденного макроса.

[Скачать готовый .geode 1.6.0 для Windows x64](https://github.com/lexaaakorolevv-cyber/turbo-disco/raw/refs/heads/route-finder-windows/downloads/local.routefinder-windows-x64-v1.6.0.geode).

## Использование

1. Установите подходящий Geode и мод, откройте обычный уровень. Справа сверху появятся кнопки **BOT**, **STOP** и **HELP**. Кнопка **BOT** также добавляется в обычное меню паузы и на экран завершения, чтобы повтор можно было запустить сразу после успеха.
2. Сначала удобно проверить **BOT → Дополнительно → Записать вручную** на простом уровне. Уровень перезапускается с начала, нажатия и отпускания округляются к следующему физическому шагу. События внутри одного шага объединяются в конечное состояние кнопки. После смерти сохраняется черновик. После завершения запускается автоматическая проверка с начала.
3. **Найти прохождение** запускает поиск. Каждый кандидат проигрывается настоящей игрой с начала, без чекпоинтов. Для самостоятельного управления нажмите **HELP** во время поиска: действия будут записываться с тем же лимитом 16 CPS. Второй **HELP** возвращает управление боту с сохранением введённого участка; после смерти бот продолжает автоматически. В обычном поиске и повторе физический ввод пользователя блокируется.
4. **Остановить** или **STOP** прекращает работу и сохраняет лучший достигнутый результат. При лимите попыток, времени или длительности попытки происходит то же самое. Статус объясняет причину. Счётчик включает попытку проверки кандидата.
5. После успешной полной проверки основной JSON сохраняется автоматически. **Сохранить макрос** повторяет сохранение проверенного результата; для непроверенного результата сохраняет `.best.json`.
6. **Загрузить макрос** открывает основной JSON текущего уровня; при его отсутствии — лучший черновик. **Воспроизвести** запускает его с начала. Загруженная отметка проверки не считается доказательством: требуется реальное повторное прохождение. Воспроизведение черновика останавливается на его конце. Загруженный лучший участок также становится исходным материалом для нового поиска.

Меню BOT приостанавливает игровую симуляцию, но не аудио; это техническая пауза мода. Время открытого меню входит в общий лимит работы. Для синхронного просмотра музыки начните воспроизведение заново. Обычная пауза игры также доступна; обработка отложенного перезапуска продолжится после снятия паузы.

## Поиск без присмотра

Оставьте игру открытой, запустите «Найти прохождение». В меню видны фаза поиска, оставшееся время и результат автосохранения. По умолчанию лимиты — один час и 10000 попыток; сохранённые пользовательские настройки Geode сохраняют приоритет, поэтому проверьте их перед долгим запуском.

Архив поиска записывается каждые 30 секунд, улучшенный лучший результат — с интервалом не чаще пяти секунд, а полный кандидат — перед отдельной проверкой. При выходе/остановке выполняется сохранение. Текущий более удачный участок длинной попытки также может попасть в автосохранение. Безопасное продолжение всегда сбрасывает настоящую игру и повторяет план с начала; восстановление объектов/чекпоинтов не используется. Прогресс после последнего автосохранения при аварийном завершении может потеряться.

Настройка **Resume saved search** включена по умолчанию. Для нового независимого поиска выключите её. Продолжение использует прежний архив/RNG/очередь, но получает новый бюджет только после вашего нажатия «Найти прохождение»; лимиты не перезапускаются автоматически. Несовместимый сеанс не загружается; при доступном совместимом `.best.json` поиск стартует от него. После обновления версии старые макросы/сеансы несовместимы.

## Лимиты

Лимит поиска фиксирован: **16 CPS**. Остальные лимиты задаются в настройках Geode до запуска операции:

| Настройка | По умолчанию |
| --- | --- |
| Число попыток, включая проверку | 10000 |
| Общее реальное время | 3600 секунд |
| Игровое время одной попытки | 600 секунд |
| Исходное окно изменения ввода | 120 физических шагов |
| Seed поиска | 1337 |

Счётчик CPS показывает нажатия за последнюю игровую секунду внутри попытки. Новые нажатия разделены минимум 15 внешними обновлениями 240 Гц (62,5 мс); внутренние полушаги не обходят лимит. Отпускания не считаются кликами и проходят без искусственного ожидания. Длительный зажим не прерывается. HUD показывает фактический счётчик и `/16 CPS`. STOP, смерть и сброс освобождают ввод штатным путём. Ручная запись, проверка и повтор сохраняют точные события без нового фильтра. Счётчик сбрасывается при новой попытке.

Общий лимит проверяется во время работы и в меню. Текущая последняя разрешённая попытка может закончиться; следующая уже не запускается. Если кандидат найден на последней попытке, он остаётся непроверенным в `.best.json`: лимит не обходится ради проверки. Дополнительно действует предел 432000 физических шагов в одной записи. Для очень длинного загруженного макроса увеличьте лимит времени одной попытки.

Поиск не гарантирует прохождение. Используются удержания без фиксированного срока отпускания, импульсы до 960 тиков, случайные продолжения и архив из 24 лучших последовательностей с ограничением числа вариантов на одном проценте. После смерти меняется ввод перед местом смерти; для прыжка откат может начинаться до его нажатия. Более ранний префикс сохраняется, одинаковые варианты с той же политикой управления отсеиваются. При застое окно отката расширяется до 2400 шагов. Сложные уровни и точные тайминги могут потребовать намного больше времени, чем доступно.

Для корабля и волны работает дополнительный ограниченный поиск будущих нажатий. Он читает настоящие координаты, скорость и текущие collision rectangles препятствий. Корабль учитывает торможение, волна — прямую траекторию и удвоенный наклон mini-wave; оба учитывают обратную гравитацию и движение влево. Кнопка остаётся нажатой, пока выбранный манёвр требует подъёма, без ограничения старым коротким импульсом. При смерти на таком участке сохранённый префикс повторяется точно, а хвост планируется с другими высотой и горизонтом.

## Что добавлено в 1.6.0

- **Калибровка.** По измерениям настоящего игрока уточняются коэффициенты гравитации, прыжка, ускорения корабля и наклона волны. Выбросы после орба, пада, dash, телепорта и смены режима не используются. Отдельные оценки для формы, mini и гравитации начинают применяться после четырёх подходящих измерений; поправка ограничена диапазоном 0,65–1,35.
- **Взаимодействия.** Прогноз учитывает жёлтый/розовый/красный/синий/зелёный/чёрный орбы, spider orb/pad, обычные пады и порталы формы, размера, гравитации и скорости. Орбы в прогнозе требуют ввода; фактическое взаимодействие всегда исполняет штатная игра.
- **Остальные формы.** Добавлен ограниченный beam search для шара, UFO, робота, паука и swing: перевороты гравитации, одиночные взмахи UFO, разная длительность зажима робота и перенос паука на противоположную поверхность. Модель приближённая.
- **Движение объектов.** По нескольким наблюдениям оценивается скорость препятствий и интерактивных объектов. Прогноз переносит их с этой скоростью на ближайшие 8 native 60 Hz единиц (около 0,13 секунды), затем фиксирует позицию. Смена направления, вращение и будущие scripted triggers заранее неизвестны.
- **Память неудач.** До 256 мест/состояний смерти влияют на стоимость маршрута, высоту и порядок правки таймингов. Причина отображается как предположение («Вероятно…»), а не доказанный анализ коллизии. Память и калибровка сохраняются в `.search.json` и восстанавливаются в совместимом сеансе.
- **Траектория.** Зелёная линия показывает выбранный прогноз; красная точка — прогнозируемый тупик. В **Дополнительно → Показать / скрыть путь** можно выключить её; настройка Geode задаёт начальное состояние. Это визуализация модели, а не гарантия безопасного пути.
- **Ручная помощь.** **HELP** либо **Дополнительно → Взять управление / Вернуть боту** переключают управление внутри текущей попытки. Реально поданные события попадают в тот же макрос. Смерть завершает помощь; полное прохождение с помощью также требует отдельного автоматического повтора с начала. Ввод помощи ограничен 16 CPS, отдельная ручная запись — без ограничения.

Прогноз использует native bounding boxes, доступные oriented corners, треугольники склонов и радиусы круглых объектов. На плотном участке рассматриваются 512 ближайших препятствий и 48 взаимодействий. Для free mode/перехода камеры при отсутствии подходящих native portal bounds используется локальное окно высоты. Dash/custom rings и телепорты не имеют полного предсказания: статус сообщает об этом, реальные события исполняет игра; может потребоваться ручная помощь. Скоростные порталы меняют в модели горизонтальную скорость, но не все сопутствующие параметры прыжка. Это не точный симулятор GD. Реальная игра оценивает каждую попытку, а полный макрос обязательно проверяется с начала без планировщика.

## Поддерживаемые режимы

Первая версия предназначена для обычных однопользовательских уровней, включая смену cube/ship/ball/UFO/wave/robot/spider/swing. Реальная пригодность поиска для этих режимов различается.

Контроллеры есть для cube/ship/wave/ball/UFO/robot/spider/swing. Для новых форм имеются тесты простых трасс с обратной гравитацией и движением влево; это не доказывает пригодности для любого реального уровня. Поиск останавливается при sideways-режиме (поворот физической оси на 90°).

Явно отклоняются platformer, two-player, dual и уровни с dual portal, practice, Start Position, Don't Reset, встроенный replay игры, editor, ignore damage, random triggers и ItemTriggerGameObject (item edit/compare/persistence). При появлении dual/practice/noclip, time warp или CBS/COS во время попытки работа останавливается. Встроенные Click Between Steps и Click On Steps временно выключаются на время операции, затем восстанавливаются.

Сторонние CBF/TPS/FPS/speedhack/replay-моды могут менять физику вне этого адаптера. Для первого теста используйте чистый профиль Geode с этим модом. Совпадение списка и версий сторонних модов не доказывает совпадение их скрытого состояния или настроек. Контрольная трасса и повторное прохождение обнаруживают многие расхождения, но не восстанавливают и не исправляют состояние игры. Межплатформенная совместимость макросов намеренно отклоняется.

## Где находятся JSON

Используется реальный `Mod::get()->getSaveDir() / "macros"`. Каталог сохранений можно найти через Geode; у него отдельное расположение на каждой платформе.

Имена:

```text
<ID уровня>_<первые 16 символов SHA-256 данных уровня>.json
<ID уровня>_<первые 16 символов SHA-256 данных уровня>.best.json
```

Основной файл — полное проверенное прохождение. `.best.json` — лучший участок или непроверенный полный кандидат, с причиной остановки и явными полями `completed` / `verified_from_start`. Не заменяет основной файл при неудаче поиска. Для локальных уровней с одинаковым ID содержимое различается по хешу. При изменении версии/данных уровня, настроек уровня, версии мода/SDK/loader, платформы, списка загруженных модов или LDM загрузка отклоняется.

Формат и модель времени описаны в [docs/FORMAT.md](docs/FORMAT.md). Запись идёт через временный файл и переименование; на Windows сохраняется резервная копия на время замены. Загрузчик умеет восстановить `.bak`, если основной файл отсутствует. Ошибки записи показываются в статусе. Размер входного файла ограничен 128 MiB.

## Сборка Windows x64

Нужны Git, CMake 3.25+, актуальный Geode CLI и Visual Studio 2022 17.14+ с C++ tools (MSVC 19.44+) либо Visual Studio 2026. Команды ниже выполняются в PowerShell из папки проекта; замените пути на свои:

```powershell
git clone --branch v5.11.1 --depth 1 https://github.com/geode-sdk/geode.git C:/dev/geode-sdk
geode sdk set-path C:/dev/geode-sdk
geode sdk install-binaries --version v5.11.1
$env:GEODE_SDK = "C:/dev/geode-sdk"
cmake -S . -B build-win -A x64
cmake --build build-win --config Release --parallel 4
```

SDK устанавливается отдельно от исходников мода. CMake намеренно требует **ровно 5.11.1** и сам загружает bindings на закреплённом commit; при другой версии нужна проверка адаптера, а не простая замена номера в `mod.json`. CMake также скачивает nlohmann/json и зависимости SDK. Команда Geode для установки бинарников должна выполняться на целевой платформе. Альтернатива — распаковать официальный `geode-v5.11.1-win.zip` в `<SDK>/bin/5.11.1/` (там должен появиться `Geode.lib`).

Результат: `build-win/local.routefinder.geode`. Windows-сборка 1.6.0 проверяется в GitHub Actions: компиляция, упаковка, семь наборов тестов и проверка архитектуры PE x64. Готовый пакет находится в `dist/local.routefinder-windows-x64-v1.6.0.geode` при наличии локальных артефактов; в CI он публикуется как `route-finder-windows-x64`.

## Сборка Android ARM64 на Linux

Нужны Geode CLI, CMake 3.25+, Ninja и Android NDK **r29** с Clang 21. Сам Geode 5.11.1 использует r29. Пример из папки проекта:

```sh
git clone --branch v5.11.1 --depth 1 https://github.com/geode-sdk/geode.git ../geode-sdk
export GEODE_SDK="$(realpath ../geode-sdk)"
# Распакуйте официальный geode-v5.11.1-android64.zip в:
# "$GEODE_SDK/bin/5.11.1/"; нужен Geode.android64.so
export RF_NDK="/absolute/path/to/android-ndk-r29"
cmake -S . -B build-android64 -G Ninja \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_TOOLCHAIN_FILE="$RF_NDK/build/cmake/android.toolchain.cmake" \
  -DANDROID_ABI=arm64-v8a -DANDROID_PLATFORM=android-23 \
  -DANDROID_STL=c++_shared -DGEODE_DISABLE_PRECOMPILED_HEADERS=ON
cmake --build build-android64 --parallel 4
```

Результат: `build-android64/local.routefinder.geode`. Для ARM32 нужны соответствующий официальный бинарник SDK и `-DANDROID_ABI=armeabi-v7a`; этот вариант здесь не проверен. На Linux нативная сборка мода не поддерживается самой Geometry Dash; Linux используется для cross compilation.

Официальные загрузки: [Geode 5.11.1](https://github.com/geode-sdk/geode/releases/tag/v5.11.1), [Geode CLI](https://github.com/geode-sdk/cli/releases).

## Установка

Закройте игру. Поместите `.geode` для своей платформы в папку `geode/mods` установленной Geometry Dash либо импортируйте локальный пакет в Geode Launcher на Android. Перезапустите игру и проверьте, что Route Finder включён. Для ПК выбирайте пакет `local.routefinder-windows-x64.geode`; пакет ARM64 не содержит Windows DLL.

При обновлении удалите прежний файл Route Finder `.geode` из `geode/mods`, затем скопируйте новый. В меню BOT проверьте заголовок `Route Finder 1.6.0`.

## Проверки

Переносимое ядро можно собрать без игры и SDK:

```sh
cmake -S . -B build-core -DROUTEFINDER_CORE_ONLY=ON
cmake --build build-core --parallel 4
ctest --test-dir build-core --output-on-failure
```

Тесты проверяют JSON/file roundtrip и замену файла, восстановление backup, недопустимые и неупорядоченные события, границы тиков, трассу, физическое расписание, seed поиска, ограниченный архив, бюджет и поиск на небольшом детерминированном препятствии. Это не тест прохождения настоящей Geometry Dash.

Результаты выполненных проверок и сценарии тестирования в игре: [docs/VALIDATION.md](docs/VALIDATION.md). Реальные сигнатуры и ссылки на исходники SDK: [docs/API.md](docs/API.md).
